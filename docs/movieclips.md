# Movieclips in the layer timeline

A movieclip is a reusable figure containing a local animation. Insert it on the selected layer, alongside other figures or clips. It does not automatically create a layer. Its internal document has its own layers and frames; Edit movieclip opens that document, Done saves the shared definition, and Cancel restores the parent. Make unique gives the selected frame a separate instance ID and definition, preserving its displayed source frame and the other appearances. Subsequent copies of that unique instance keep its new ID when it is absent from the destination frame.

Use Animation → New movieclip, Movieclip from selection, or Movieclip from frame range. Selection capture creates a reusable pose; range capture preserves the selected motion. Connected figures are included together. Replacement preserves surrounding figures and draw order. Interleaved selections that cannot be represented by a single container are rejected atomically.

Drawing layers can be captured too; All figures includes every drawing shown in the range. Inside the clip, each drawing layer holds ordinary drawing keys: one key per exposure, each with its own pose, and consecutive frames showing the same drawing become one hold. They paint, copy and re-time like any drawing layer. Captured drawings get fresh cel identities, so the clip and the project never share or overwrite each other's pixels; the project's drawing layer simply stops showing the captured exposures. A clip is never placed on a drawing layer, which holds only drawing cels: when a drawing is the anchor, the clip goes on the lowest selected figure's layer, and a clip made only of drawings gets a new figure layer, named after the clip, directly above that drawing layer, in the same undo step. The project keeps the clip's cels resident like its own instead of repeatedly decoding them.

New movieclips follow their presence in layer frames. Inserting a clip adds it to the current pose without extending the scene to fit its source animation. Simple Add carries the same instance forward and advances it. Held exposures advance the internal animation on every output frame. Source duration determines looping, not scene duration.

Missing frames pause the same instance: a clip in scene frames 1, 2, 3 and 5 shows source frames 1, 2, 3 and 4 at matching FPS and speed 1. Object copy/cut and paste within the same document keep a movieclip's ID, playback settings, position and owning layer. Pasting where that ID already exists creates a fresh instance on the original owning layer, preserving the copied source phase and playback settings. Existing instances stay unchanged. The new instance shares the captured figure definition; Make unique separates the definition for independent content editing. Range paste resolves collisions once for the whole range, so a fresh instance keeps one ID across its destination frames. A paste into a held exposure begins at the selected frame and follows that exposure. Duplicate, library insertion and object paste from another document create independent identities. Ordinary figures still receive new IDs when pasted. Same-layer frame copies keep identity; cross-layer and cross-project frame copies remap identities once per range and retain the copied source phase. Moving frames to another layer retains consumed steps on the source, preserving any later source appearance. Layer visibility and opacity do not affect the clock.

The inspector shows the sampled source frame out of the total, source duration in frames and seconds, source FPS, and the current scene frame. Playback provides Loop, Once/hold, Once/hide, Single frame, Start frame (Hold frame in Single frame mode), and speed; the speed field is disabled for Single frame. Transform includes position, scale, angle, opacity, and z-index. Edit clip and Make unique are the instance's quick actions under its name, beside Duplicate and Delete; a double-click on the name renames the definition. Add to next keyframes is in the titled **Extend** section, and Break apart frame, Bake animation and Export movieclip in **Bake and export**; both remember being open. Add to next keyframes retains the numeric z-index and same-layer stacking position, leaves existing appearances unchanged, and reports added or already-present keyframes inline. It never creates scene frames. Start, End, Restart and Split controls are removed. Inspector playback settings apply to the selected instance across its appearances without inserting time or changing pose-key boundaries. Scrubbing backwards and rendering exports produce the same internal frame as playback.

Deleting a selected movieclip removes it only from the current output frame, including inside a hold. Other clips and surrounding poses remain intact; the missing frame pauses the instance's clock. Applying Delete to selected frames removes only those requested frames' occurrences. Delete on the timeline still removes time according to the normal frame controls.

Break apart frame replaces only the current output frame with editable figures. It preserves every other frame, including the original outer motion curves and unrelated figures on the layer. Adjacent breaks reuse child identities. A continuation record counts the broken frame as a consumed playback step, even after its editable children are moved or deleted. Bake animation expands the instance while preserving prior breaks. Each operation is one undo step.

There are no per-figure clip bars or separate property timelines. Outer posing, clipboard operations, holds and tweens use the layer's frame cells. Several clips can share one row; use another layer when their frame editing needs to be independent.

Definitions live in the figure table as `_styk.movieclip`. New instances use `_stykMovieclip.clock: "presence"`; their stable `unique_id` owns the clock. A cached sparse span index integrates authored presence and speed. `_styk.movieclipContinuations` on retained poses records consumed replacement frames. Layer keys can carry `movieclipPatches`. An optional `orderIndex` on extension patches preserves stacking among equal-depth figures without capturing unrelated poses. `patchOnly` boundaries expose those editable frames without adding interpolation control points to the underlying curves. Clipboard, validation, history and source retention include those references. `_movieclipSample` and runtime geometry remain transient.

Creation uses those same sparse replacements over the requested range. It keeps
the original layer pose keys as its interpolation baseline, reuses identical
container sources, and records consumed steps for replaced presence clips.
Unrelated layer poses are neither materialized nor copied into creation history.
The captured definition retains the selected figures' source curves, including
fractional sampling through the last output frame. Definition-only capture does
not change the parent sheet. `tests/movieclip-creation.test.mjs` checks bounded
history, source sharing, eased crops, connected layers, reopening and undo.

Existing placement-based project clips retain their saved bounds and phase for compatibility. Newly inserted copies use presence playback. Imported clips may retain source documents to preserve cropped easing exactly; cropped nested presence clips retain their original source phase. Geometry is shared by instances sampling the same immutable definition and time, with bounded local caches.

STYK saving retains the editable nested documents. Pivot export expands the evaluated scene in the worker; image, SVG and video exports use the same evaluator. Existing export limits remain: at most 100,000 Pivot output frames / two million objects, and 5,000 ticks / 250,000 objects for interactive Bake. Pivot cannot represent one opacity operation around overlapping child figures; unsupported expansion still reports that limitation.

Verification: `tests/movieclip-presence.test.mjs` covers progression, gaps, removal, timing, frame replacements, easing preservation, clipboard identities, nested crops, history and export. `tests/layer-movieclips.test.mjs` retains conversion and legacy compatibility coverage. `tests/movieclip-commands.browser.mjs` exercises the actual inspector, mode switches and binary STYK save/reload.
